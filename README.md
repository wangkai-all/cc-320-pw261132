# 返利核对台（虚构演示）

按「**供应商集团 + 品类 + 季度**」整段累计采购额，套用阶梯返利；把**已确认台账**与**试算**严格分开；退货和供应商归属更正可追溯地改变历史段。

> 全部公司与金额均为虚构占位，仅用于产品与技术演示，**不构成税务、法律或会计意见**。金额内部一律以「分」的整数运算。

## 运行

要求 Node.js ≥ 22.5（使用内置 `node:sqlite`，无需安装依赖，也无构建步骤）。

```bash
npm start          # http://127.0.0.1:3000，首次启动自动导入虚构种子数据
npm run serve:clean # 删除本地数据库后重建种子再启动
npm test           # 24 项测试：口径、退货、试算过期、并发、增量一致性、任务恢复、HTTP
```

数据默认写入 `data/rebate.db`（已被 .gitignore 忽略）。可用 `REBATE_DB=...`、`PORT=...` 覆盖。

## 核心业务规则

### 1. 整段累计，套单档，不逐单相加

一个累计段 = `(供应商集团, 品类, 季度)`。同一集团下**多个采购实体、多个供应商**的采购共同推动同一门槛；跨档后**整段合格金额**按新费率计算，而不是逐单套档再相加。

```
合格金额 = max(0, 采购总额 − 退货总额)          （同一段内）
返利     = round_half_up(合格金额 × 命中档费率)   （整段只套一次）
```

逐单相加法只出现在钻取面板里作为**对照解释**（展示高估/低估多少），永不参与台账。

### 2. 两种聚合维护策略（可在页面顶栏 / 设置页切换）

| 操作 | `incremental`（默认） | `recompute` |
| --- | --- | --- |
| 新增采购 | 读 1 段缓存 + 累加 + 重套整段阶梯，`O(实体数)` | 重扫该段全部事件 |
| 退货 | 更新原期间段聚合，`O(实体数)` | 重扫原期间段全部事件 |
| 规则变更 | 每段复用缓存金额换费率，`O(受影响段 × 实体数)`，**不读事件明细** | `O(受影响段事件总数)` |
| 供应商归属更正 | 仅重建原/新集团受影响的段 | 同样范围，但从事件重扫 |

- **正确性**：两条路径共用同一个 `applyTiers` 与分摊函数，结果必须逐分一致；`GET /api/consistency` 对每个段“重扫事件从头算”与存储聚合对比，并核对实体分摊合计 = 整段返利。
- **性能**：增量路径避免全历史扫描；规则变更只动“该合同覆盖集团+品类”的期间段（费率是整段乘数，历史段同样需要重算），并通过可恢复任务分批提交。
- 事件集用**可交换摘要**（各事件哈希按位异或）增量维护，交易/退货的加入与移除都能 O(1) 更新，同时与全量重算得到同值；用于校验与过期判断。
- 切换策略只影响后续写入与任务，**不追溯改写**已产生的聚合；需要时用“全量对照重算”重建。

### 3. 试算 vs 正式台账

- `calc_snapshots`：试算/假设快照，永远不是台账来源。每条记录写明基线段版本、输入摘要、规则版本、实体分摊与命中档位。
- `confirmed_entries`：正式台账，只追加。数据库触发器禁止 `UPDATE` / `DELETE`；确认、补记（正数）与回补（负数）都以新分录记录。
- 确认前强制校验：段版本、输入摘要、规则版本、段是否待重算。任一不匹配 → `409 stale_snapshot`，**旧试算一律拒绝**，绝不“尽量确认”。
- 假设（what-if）门槛快照 `confirmable = false`，确认时返回 `409 what_if_not_confirmable`，也不改变正式聚合。

### 4. 多实体共享门槛的确认与回补

- 分摊按各实体净额权重，**最大余数法**（BigInt）确定性分配，余数按实体键稳定排序；合计严格等于整段返利，否则直接抛错禁止确认。
- 确认按 `目标 − 已确认` 的差额分配：并发或重复确认时，第二次差额为 0，不会重复分配。
- 补记（`topup`）用于“已确认后又新增采购/跨档”的已审阅追加，依然以当前段应得为上限。
- 退货使历史应得下降后，若已确认更高，确认接口返回 `409 clawback_required`；多确认部分必须通过显式回补（负分录）冲销。

### 5. 并发安全

- 写事务使用 `BEGIN IMMEDIATE`（最外层），两个确认请求被串行化；内层嵌套使用 `SAVEPOINT`。
- `ledger_requests` 以带命名空间（`confirm:` / `clawback:`）的幂等键唯一约束实现请求重放；`confirmed_entries` 分录键再加实体维度。
- 测试 `test/concurrency.test.js` 用独立 worker 线程 + 独立 SQLite 连接同时确认，验证同一笔返利最多分配一次。

## 退货与归属更正的可解释影响

每次写入都会生成 `changes` + `change_impacts`：

- 受影响期间段、合格金额变化、返利变化、变化前后的完整段快照；
- 因此**过期**的快照 ID 列表；
- 页面「变更追溯」可按事件查看：一笔 3000 元退货如何让 2026-Q1 返利从 1570.00 → 1495.00（−75.00），以及它让哪个试算失效。
- 供应商归属更正会同时记录原集团与目标集团两侧的段变化、保留 `supplier_group_history`，并给出**确认超额暴露**（已确认高于新应得的金额）供回补。

## 可恢复任务

规则变更会创建 `recalc_jobs` / `recalc_job_items`：按批提交，每处理完一项即持久化结果与影响。任务可暂停；进程中断后 `pending` 项继续，`done` 项不重复处理。任务记录策略快照、读取事件数、用时与逐段结果。

## 页面功能

- **总览**：累计额、应得（试算）、已确认、确认超额；待重算提示；最近变更与任务。
- **期间段**：筛选；钻取阶梯位置、距下一档差额与跨档增量；整段法 vs 逐单法对照；实体分摊；事件；变更轨迹；试算列表（可确认/已过期/假设）；正式台账；回补。
- **采购事件**：录入采购；退货必须关联原采购并自动追溯原期间。
- **合同与规则**：规则版本化；调整后自动创建重算任务并标记历史段待重算。
- **变更追溯**：逐段前后对照与过期快照数。
- **重算任务**：推进/暂停/恢复、全量对照重算、逐段结果。
- **设置与审计**：策略切换、一致性自检、审计日志、全量 JSON 导出。

```
src/ledger.js    确认、补记、回补、幂等与并发控制
src/jobs.js      可恢复批量重算
src/server.js    HTTP API + 静态资源
src/seed.js      虚构演示数据
public/          无构建前端
test/            口径、API、并发测试
```
